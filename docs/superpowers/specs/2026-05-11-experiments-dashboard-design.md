# Experiments Dashboard — Design

- **Date:** 2026-05-11
- **Author:** houyuxin (via brainstorm)
- **Status:** approved (ready for implementation plan)

## Goal

A single self-contained HTML dashboard that lets the user (and their
teammates) see, at a glance:

1. The **current best experiment** — its name, headline score, agent
   workflow, and key strategies — so progress is easy to introduce to
   teammates.
2. The **full set of experiments** — config, scores, and strategy
   differences — in one sortable table with click-to-expand detail.

Out of scope: live experiment monitoring, editing config from the UI,
running experiments from the UI, multi-user authentication, hosting
infra. The dashboard is a read-only artifact regenerated by a script.

## Constraints

- **Zero-install for readers.** Open the HTML file → it works. No
  server, no Python, no internet.
- **Single source of truth per fact.** Scores come from
  `results/<exp>/summary.csv`. Experiment-was-LEDGERed comes from
  `LEDGER.md`. Config comes from `config/experiments.yaml`. Narrative
  comes from the matching retro file. Nothing is hand-maintained twice.
- **Forgiving on data drift.** Retros do not strictly follow
  `_template.md`; the parser must work on the actual file shapes (e.g.
  `2026-05-08-exp006c_tools_cross-report.md` uses `## Strategy` and
  custom comparison tables).
- **Conda `ssda` is the build env.** Cloud-box rules don't apply — this
  is a local-build artifact. Build script is fine as a regular Python
  module under `src/ssdataagent/`.

## Data sources

Read in priority order:

1. **`docs/experiments/LEDGER.md`** — canonical list. Each markdown
   table row becomes one dashboard row. The `retro` column links to the
   matching retro file (either `docs/experiments/<date>-<exp>-report.md`
   or `docs/report/<date>-*.md` for older pilots). Rows naming two
   experiments (e.g. `exp006c_tools_cross + exp006c_tools_long`) are
   treated as a single logical "experiment family" — the parser splits
   on `+` and `,` and merges results from each.

2. **`results/<exp_name>/summary.csv`** + **`done.flag`** —
   authoritative numbers. `done.flag` is the source of truth for what
   actually ran (`prompt_variant`, `llm_model`, `llm_provider`,
   `finished_at`, `n_dataset_condition_cells`); per STRUCTURE.md it
   overrides yaml if they disagree.

3. **`config/experiments.yaml`** — pulls each experiment's `datasets`,
   `conditions`, `n_rows`, `prompt_variant`, `max_iterations`,
   `train_eval_split` for the detail view.

4. **Retro reports** — `docs/experiments/<date>-<exp>-report.md` and
   `docs/report/<date>-*.md`. Parser is **heading-agnostic** (see
   "Parsing robustness" below).

Results directories that aren't named in `LEDGER.md` (smoke runs,
diagnostic re-attempts) are excluded by default. An
`--include-unledgered` flag exists for inspection.

## Architecture

```
scripts/build_dashboard.py          # CLI entry: `python scripts/build_dashboard.py`
src/ssdataagent/dashboard/
  __init__.py
  ledger.py                         # parse LEDGER.md → list[LedgerEntry]
  results.py                        # walk results/<exp>/ → ExperimentResults
  config.py                         # load config/experiments.yaml → ExperimentConfig
  retros.py                         # parse retro .md files → RetroSections
  model.py                          # merge into DashboardExperiment; pick champion
  render.py                         # build HTML from Jinja template + embedded JSON
  templates/
    index.html.jinja                # single-page template (HTML + CSS + JS inline)
docs/dashboard/
  index.html                        # generated; committed to git
tests/dashboard/
  test_ledger.py
  test_results.py
  test_config.py
  test_retros.py
  test_model.py
  test_render.py
  fixtures/                         # mini LEDGER, results/, retros, yaml
```

### Module boundaries

- `ledger.py`, `results.py`, `config.py`, `retros.py` are **pure
  parsers**: each takes a path, returns a dataclass, never touches the
  others. Independently testable against fixture files.
- `model.py` is the **merger**. It joins a `LedgerEntry` → matching
  `ExperimentResults` → matching `ExperimentConfig` → matching
  `RetroSections` into one `DashboardExperiment` per LEDGER row.
  Derives:
  - `overall_mean_full_agent` — mean of pass_rate over all
    (dataset, T-type) cells present in `summary.csv` for the
    `full_agent` condition. Cross-sectional datasets only have
    T1/T2/T3; missing T4/T5 cells are **not zero-filled** (would
    unfairly punish cross-sectional runs against longitudinal). The
    detail panel still shows `—` for absent cells.
  - `by_type` — per-T mean across datasets (for the bar chart). A T
    with no data across all datasets is omitted from the chart.
  - `is_champion` — single row with max `overall_mean_full_agent`,
    excluding rows tagged `is_pilot`. Ties are broken by most recent
    `date`.
- `render.py` only takes a `Dashboard` payload and the Jinja template;
  it doesn't know about file paths.
- The page's vanilla JS only knows the embedded JSON shape — no
  `fetch()`, no CDN.

### Data flow

```
LEDGER.md ──┐
results/   ─┤
yaml       ─┼──► model.assemble() ──► Dashboard payload ──► render.write_html() ──► docs/dashboard/index.html
retros/    ─┘                              │
                                           └─ (also writable to docs/dashboard/data.json for debugging)
```

### Run modes

- `python scripts/build_dashboard.py` — full rebuild from LEDGER.
- `python scripts/build_dashboard.py --cache` — writes parsed retro
  sections to `docs/dashboard/.cache/<exp>.json` so subsequent builds
  can skip the markdown parse for unchanged retros. This is the
  "one-time parsing as fallback" knob.
- `python scripts/build_dashboard.py --strict` — exit non-zero if any
  LEDGER row is missing a `results/<exp>/done.flag` or retro file.
  Useful in CI later. Default mode is forgiving.

### Decisions taken

- **Module placement.** Parsing/rendering lives under
  `src/ssdataagent/dashboard/` (mirrors the existing
  `src/ssdataagent/experiments/runner.py` layout). CLI entry is the
  only thing in `scripts/`.
- **Committing the HTML.** `docs/dashboard/index.html` is committed to
  git. Trade-off accepted: diff noise when scores change, in exchange
  for teammates being able to `git pull && open docs/dashboard/index.html`
  with no extra steps.

### Components (vanilla JS, no framework)

- **`ChampionCard`** — renders the single experiment where
  `is_champion === true`. Headline + per-T bar chart + curated strategy
  bullets. Strategy bullets are pulled from the retro's parsed sections
  (see Parsing robustness for slot mapping).
- **`ExperimentsTable`** — sortable on every column (click header to
  toggle asc/desc). Filters: free-text search (exp_name, hypothesis,
  prompt_variant); model dropdown; "show pilots" toggle (default on);
  "show only completed" toggle (default on, hides any LEDGER row
  without a `done.flag`).
- **`DetailPanel`** — opens inline below the clicked row. Sections:
  Config (from yaml + done.flag), Scores (per-dataset × per-condition ×
  T1–T5 mini-heatmap), Retro prose (pre-rendered HTML for Hypothesis /
  What changed / Headline / Lessons), link to the raw retro `.md` on
  disk.
- **`Charts`** — bar charts are pure CSS/HTML `<div>` widths. The
  heatmap is a CSS grid with cells colored by a 5-stop scale
  (0 → 0.5 → 1.0). No charting library; keeps the HTML standalone.

### Pilots vs experiments

LEDGER rows whose `exp_name` starts with `pilot_` are tagged as
"pilot/baseline" with a muted style and are excluded from the
champion-mean calculation (they're the comparison baselines, not the
agent we're optimizing). A filter-bar toggle shows/hides them.

### Empty / missing data

- LEDGER row with no matching `results/<exp>/summary.csv` → row still
  renders with config + retro prose and a `— no scores —` marker.
- LEDGER row with no matching retro → row renders with just LEDGER row
  data and a "(retro not found)" note.
- The dashboard never crashes on partial data.

## Parsing robustness

Retro parsing is **heading-agnostic** because real retros drift from
`_template.md` (`## Strategy` vs `## Hypothesis`, custom comparison
tables, etc.). The parser:

1. Reads YAML frontmatter if present →
   `{exp_name, date, model, git_sha, baseline_exp, hypothesis, ...}`.
   These fields are trusted when present.
2. Walks all `##` headings with a real markdown parser
   (`markdown-it-py`) and builds `dict[heading_text → markdown_body]`
   plus per-section bullet lists.
3. Model layer fills slots via a candidate list:
   - **Hypothesis:** `frontmatter.hypothesis` → `## Hypothesis` →
     `## Strategy` → first paragraph after H1 → LEDGER `hypothesis`.
   - **What changed:** `## Setup` → `## Strategy` →
     "Code change(s) under test" bullet → LEDGER `hypothesis`.
   - **Results headline:** LEDGER `headline` column (most consistently
     authored field) → `## Results` first line.
   - **What worked / What didn't / Lessons:** named bullets under
     `## Retro` → matching named bullets anywhere → empty.
4. Any slot that comes up empty renders as `—` instead of crashing.

## Error handling

- Multi-exp LEDGER rows split on `+` and `,`; if only one of the named
  experiments has results, render with what's available + a `(partial)`
  badge.
- Malformed `summary.csv` → log a warning, skip that experiment's
  scores. Don't crash.
- `--strict` mode turns missing-result / missing-retro / malformed-csv
  into non-zero exit. Default mode is forgiving.
- Builder logs at INFO: `parsed N LEDGER rows, M results dirs, K
  retros, champion = <exp>`. At WARNING: every missing/partial join.
  No silent failures.

## Testing

Unit-level, with fixture data rather than the real repo.

- `tests/dashboard/fixtures/` — 3-row mini-LEDGER, two mini retros (one
  template-conformant, one drift-y), two mini
  `results/<exp>/summary.csv`, one mini `experiments.yaml`.
- `test_ledger.py` — table parses to N entries; multi-exp rows split;
  missing column tolerated.
- `test_results.py` — `summary.csv` →
  `{condition × dataset × type → pass_rate}`; computes
  `overall_mean_full_agent` correctly; tolerates missing T4/T5
  (cross-sectional case).
- `test_config.py` — yaml loaded for an experiment by name; missing key
  tolerated.
- `test_retros.py` — frontmatter parsed; heading-agnostic lookup hits
  both template and drift cases; empty retro doesn't crash.
- `test_model.py` — `assemble()` picks the correct champion; pilots
  excluded from champion calc; partial-data row renders with badges.
- `test_render.py` — smoke: builder runs against the fixture set,
  output HTML is non-empty and contains the expected exp names and at
  least one chart element.

No browser/JS tests. The JS is small enough (~150 lines for
sort/filter/detail-toggle) to verify by eye. If it grows, add a
Playwright smoke later.

## Non-goals (explicit YAGNI)

- No diff-two-experiments view in v1. Detail panel for one experiment
  at a time. Easy to add later if the table-only comparison proves
  insufficient.
- No timeline / scoreline plot in v1. The table + champion card is the
  primary view.
- No CI integration in v1. Build is manual: run the script when LEDGER
  or results change. Adding a pre-commit / post-experiment hook is a
  future increment.
- No editing config from the UI. Read-only.
- No per-user state (no saved filters, no auth).
